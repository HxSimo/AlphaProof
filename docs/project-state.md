## Preserved M6 milestone

M6 evaluates operational compliance, economics and statistical evidence independently. Excluded provenance returns `NOT_ELIGIBLE_FOR_REAL_CAPITAL` before policy criteria, while a valid forward profile with disabled inference returns `INSUFFICIENT_EVIDENCE`. Every result keeps automatic funding false. Corrections append a superseding receipt and event without mutating the old report.

Canonical audit events use monotonic experiment sequences and prior-event hashes. Domain-separated leaves form deterministic Merkle trees; batches require contiguous non-overlapping ranges and the exact predecessor hash. Export verification requires every audit event, leaf, proof and finalized receipt, reconstructs each root, rejects version/provenance changes and binds the selected result. A fresh Node process recomputes the corrected eligibility receipt before checking the selected leaf and two-batch chain.

`ProofOfAlphaRegistry` is deployed at `0xc391ad7e4826a2c1ecc56e845098b8c1b580eebd` on Arc Testnet. Deployment transaction `0xc21d3035148ac4bcc91632cb7f6cee8a82fdb91c3ca8cab326600e7f4b0964b6` and both publications are finalized. The first root for sequences 1–15 remains retained; transaction `0xea2936138e4d8ced9e6408ec0585d9201c07a6156bff1d44db1e4cf18d2475f4` appended the canonical sequence-16 correction with predecessor `0xe44d3ccbf191f68a291c6b6e6647f9df7f3871cbc73a6e062f32df45e9a13f5c`. The [v2 evidence](evidence/m6-registry-publication.json) and both v1 artifacts preserve the history. Periodic anchoring proves integrity after publication; it is not independent proof that server receipt preceded execution.
