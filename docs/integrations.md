## Completing a verification

1. Start from each dependency's official source list; record the exact page/release/address-book commit and observation date. Confirm environment using the selected RPC `eth_chainId`. Never use an EVM chain ID as a CCTP domain.
2. Resolve token/contract interfaces, decimals, deployment and upgrade/admin code. Archive block number/hash, `eth_getCode` and code hashes for the exact environment. No provider credential enters a public manifest.
3. Run fixed-block operation, rounding, cap, liquidity, gas and failure tests. Archive raw amount-specific quotes, feed round/heartbeat, fee API payloads and exact parser/adapter versions. A displayed APY is not an accrual input.
4. For CCTP, validate each direction separately, actual burn/finality/attestation/mint, Standard fee-switch behavior, destination gas funding, retries and duplicate message handling. Store real transaction hashes only from receipts. The two real test transfers validate a route, not the funding of three virtual portfolios.
5. Prove replay from captured bytes and required versions. Add evidence URIs and content hashes with their kind/date; empty or partial evidence cannot enable a gate. M5 additionally requires actual test-token vault and transfer round trips.
6. Create a new versioned manifest/profile, preserve the old version, compute and review its seal, rerun the complete validation, and update fact sheets/ADRs/state. M0 `config:seal` is an initial authoring command; it is not permission to overwrite frozen history. M3 start must inspect evidence artifacts and policy capture rules, not merely trust a manually entered status.

## Deterministic unavailable boundary

`requireDependency` throws `DEPENDENCY_UNVERIFIED` for every unresolved external dependency before a caller can capture data. `tests/fixtures/dependency-unavailable.json` records the synthetic unavailable response: no block, quote, raw-object hash or transaction. Tests apply this fixture across every dependency. Actual protocol mechanics/rounding fixtures are M2/M5 deliverables and are not counted complete because this fixture exists.

## Scope and limitations

Use direct viem contract calls behind the single CCTP adapter initially; Bridge Kit is optional call convenience requiring a separate version/support check if selected. It never owns accounting. The Graph is optional; no credentials are needed until a useful selected subgraph exists. No second bridge/router fallback is allowed. Arc mainnet remains an explicitly disabled future profile, with its market, route and mainnet gas-funding policy unverified.

S3 production endpoint, credentials, restore/retention guarantees and hosting deployment are outstanding. M2 implements memory, filesystem and injected S3-compatible archive interfaces plus cross-process restore; only the first two were tested. Publication/relayer keys belong in operator secret storage; no agent decision key is collected. Financial estimates require actual capture and calibration; no fixed fees, liquidity, live yield or route success are inferred from these documents.
