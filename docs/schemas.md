# Canonical contracts v1

The executable definitions are in `packages/schemas/src`; `pnpm schemas:generate` publishes `schemas/generated/v1.json` and `pnpm schemas:check` detects drift. JSON Schema validates structure. Zod refinements plus `packages/config` enforce sums, temporal ordering, uint256 maximums, evidence and cross-file relationships; **JSON Schema alone is insufficient**.

Amounts use canonical decimal strings in minimum units, up to uint256 with no leading zeros, sign, exponent or fractions. Small scales/counters and basis points may be integer numbers. IDs are bounded lowercase ASCII. Contract addresses and hashes are lowercase hex. UTC timestamps use exactly millisecond precision. Action `validUntil` is Unix seconds as a positive decimal string for later EIP-712 signing.

Allocation entries contain network, instrument and positive weight, sorted by `networkId/instrumentId`, without duplicates and totaling 10,000 bps. The frozen allowlist resolves asset identity and protocol exposure. Zero-weight entries are omitted. Agent, experiment, scenario, declared version, policy, transfer policy, network profile, nonce, expiry, expected portfolio version and cost/transfer/slippage bounds are all required signed intent fields. The SDK/type-hash vectors and cryptographic signature validation are M3 work.

Core versioned contracts cover AgentVersion, ExperimentPolicy, CapitalScenario, ActionIntent, ExecutionPlan/Receipt, TransferIntent/Receipt, ValuationCheckpoint, EvaluationReceipt, AuditEvent and CommitmentBatch. Plans are dependency ordered. Simulated transfers cannot claim real transaction or attestation hashes. Settlement cannot simultaneously retain a receivable. Missing valuation inputs cannot be labeled fresh. Excluded provenance and a disabled statistical method cannot become eligibility. Full accounting transitions, policy authorization, batch continuity and signatures are implemented at their milestones, not implied by schema parsing.

M1 adds `ShadowPortfolio`, `AccountingReceipt`, `AccountingCost`, `PositionValuationInput` and `PortfolioValuation` at accounting version `1.0.0`. Portfolio values remain six-decimal USDC strings; asset views retain their original and canonical scales. A balance family is the canonical economic balance, so native and ERC-20 views of the same Arc USDC cannot be initialized twice. Signed modeled PnL uses canonical int256 strings. The configured destination-attempt ceiling travels in portfolio state so replay cannot inherit a changed runtime default.

Accounting receipts are strict discriminated objects for no-effect rejection, reservation, attempted cost, allowance, deposit, withdrawal, swap, payable settlement, transfer transitions, accrual and closure. Every receipt binds an operation, scenario, provenance, expected state version, observation time and archived source hashes. Costs declare a category, funding path and source hash. Shape validation is followed by reducer invariants; parsing a receipt alone does not prove an economic transition is legal.

POA-CJSON-1 serializes plain JSON with recursively sorted UTF-16 keys, stable JSON escaping, UTF-8 bytes and preserved array order. It rejects undefined, unsafe/fractional numbers, negative zero, BigInt wire values, getters, cycles, nonplain objects and lone surrogates. It does not normalize Unicode. `contentHash` is keccak256 of those bytes. Config file hashes bind a manifest bundle; this local seal is neither EIP-712 typed-data hashing nor an on-chain commitment. EIP-712 array/type hashing is explicitly a separate M3 deliverable.

Unknown fields fail. No schema coerces balances. Stable errors are exported by `@poa/domain`, including `ACCOUNTING_INVARIANT`, `OPERATION_CONFLICT`, `INVALID_TRANSITION`, `CLOSED_PORTFOLIO` and `PAYABLE_NOT_FOUND`. The public API still has no mutation endpoints; readiness failures return `DATABASE_UNAVAILABLE` without connection details. Schema refinements describe validation failures internally; M3 maps them to the stable API error envelope.

Changes to wire shapes or semantic rules need schema/version review and replay vectors. No active experiment exists in M0. Later correction/export paths must preserve the exact old schema and engine rather than silently reinterpret a historic receipt.
