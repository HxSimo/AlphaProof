# Canonical contracts v1

The executable definitions are in `packages/schemas/src`; `pnpm schemas:generate` publishes `schemas/generated/v1.json` and `pnpm schemas:check` detects drift. JSON Schema validates structure. Zod refinements plus `packages/config` enforce sums, temporal ordering, uint256 maximums, evidence and cross-file relationships; **JSON Schema alone is insufficient**.

Amounts use canonical decimal strings in minimum units, up to uint256 with no leading zeros, sign, exponent or fractions. Small scales/counters and basis points may be integer numbers. IDs are bounded lowercase ASCII. Contract addresses and hashes are lowercase hex. UTC timestamps use exactly millisecond precision. Action `validUntil` is Unix seconds as a positive decimal string for later EIP-712 signing.

Allocation entries contain network, instrument and positive weight, sorted by `networkId/instrumentId`, without duplicates and totaling 10,000 bps. The frozen allowlist resolves asset identity and protocol exposure. Zero-weight entries are omitted. Agent, experiment, scenario, declared version, policy, transfer policy, network profile, nonce, expiry, expected portfolio version and cost/transfer/slippage bounds are all required signed intent fields. M3 defines the EIP-712 `ActionIntent` type in `@poa/sdk`. The array field is bound as `keccak256(POA-CJSON-1(targetAllocation))`; typed-data bytes, intent hash, EIP-712 digest and signed-bytes hash are stored separately. Golden signature tests cover domain and content changes.

Core versioned contracts cover AgentVersion, ExperimentPolicy, CapitalScenario, ActionIntent, ExecutionPlan/Receipt, TransferIntent/Receipt, ValuationCheckpoint, EvaluationReceipt, AuditEvent and CommitmentBatch. Plans are dependency ordered. Simulated transfers cannot claim real transaction or attestation hashes. Settlement cannot simultaneously retain a receivable. Missing valuation inputs cannot be labeled fresh. Excluded provenance and a disabled statistical method cannot become eligibility. Full accounting transitions, policy authorization, batch continuity and signatures are implemented at their milestones, not implied by schema parsing.

M1 adds `ShadowPortfolio`, `AccountingReceipt`, `AccountingCost`, `PositionValuationInput` and `PortfolioValuation` at accounting version `1.0.0`. Portfolio values remain six-decimal USDC strings; asset views retain their original and canonical scales. A balance family is the canonical economic balance, so native and ERC-20 views of the same Arc USDC cannot be initialized twice. Signed modeled PnL uses canonical int256 strings. The configured destination-attempt ceiling travels in portfolio state so replay cannot inherit a changed runtime default.

Accounting receipts are strict discriminated objects for no-effect rejection, reservation, attempted cost, allowance, deposit, withdrawal, swap, payable settlement, transfer transitions, accrual and closure. Every receipt binds an operation, scenario, provenance, expected state version, observation time and archived source hashes. Costs declare a category, funding path and source hash. Shape validation is followed by reducer invariants; parsing a receipt alone does not prove an economic transition is legal.

POA-CJSON-1 serializes plain JSON with recursively sorted UTF-16 keys, stable JSON escaping, UTF-8 bytes and preserved array order. It rejects undefined, unsafe/fractional numbers, negative zero, BigInt wire values, getters, cycles, nonplain objects and lone surrogates. It does not normalize Unicode. `contentHash` is keccak256 of those bytes. Config file hashes bind a manifest bundle; this local seal is neither EIP-712 typed-data hashing nor an on-chain commitment. EIP-712 array/type hashing is explicitly a separate M3 deliverable.

Unknown fields fail. No schema coerces balances. Stable errors are exported by `@poa/domain`, including accounting, experiment, signature, concurrency, quota and job failures. M3 adds strict agent registration, version/revocation, experiment, signed-envelope, action, portfolio-response, correction and queue-job contracts. Mutation endpoints map schema and authenticated policy failures to stable error envelopes; readiness failures return `DATABASE_UNAVAILABLE` without connection details.

M4 adds strict `ReferencePortfolio`, `ScenarioCheckpoint`, `ScenarioEvaluation` and `M4ReplayBundle` contracts. References bind their frozen kind/instrument, initial-distribution hash, period, valuation convention and terminal availability. Checkpoints contain exactly one agent and two fixed-reference projections at one time. Descriptive amounts and basis-point returns remain integer strings; unavailable values and comparisons are `null`, never zero. Replay binds content-addressed raw inputs, amount-specific quote-set hash, checkpoint hash and evaluation hash.

M5 adds `CctpRoute`, `CctpTransfer`, `TransferLifecycleEvent`, `ChainReceiptEvidence` and `YieldSchedule`. Routes distinguish EVM chain IDs from CCTP domains and freeze Standard mode, finality threshold and destination retry bounds. Live burn and destination events require finalized successful receipts; attestation readiness requires archived bytes. Synthetic events cannot claim chain receipts or attestations. A finite live yield schedule requires deployed-vault, deployment and funding transaction evidence and must be frozen before experiment start; synthetic schedules cannot carry transaction hashes.

M6 adds `CommitmentLeaf`, `CommitmentLeafSet`, `MerkleProof`, `RegistryPublicationReceipt`, `ExportObject`, `ReproducibleExport` and `DashboardResponse`. Leaves bind the audit object type/schema, experiment, sequence, content hash and audit-event hash under one explicit domain. Exports require the complete frozen hash set, engine versions, signed bytes, raw inputs, receipts, checkpoint/evaluation objects, ordered audit chain, every leaf/proof/batch and finalized publication receipt. Verification checks semantics beyond JSON Schema: exact object hashes, full sequence coverage, batch predecessors, root reconstruction, one proof per leaf, one receipt per batch, selected-result binding, provenance consistency and supported engine versions.

Changes to wire shapes or semantic rules need schema/version review and replay vectors. No active experiment exists in M0. Later correction/export paths must preserve the exact old schema and engine rather than silently reinterpret a historic receipt.

## M7 operational and demo objects

`IncidentInput`/`IncidentRecord` v1, `OperationsPolicy` v1 (policy version 0.7.0), `OperationsSnapshot` v1, `DemoDiagnostic` v1, `DemoSession` v1 and `DemoRehearsal` v1 are generated alongside the financial contracts. `SyntheticProfile` binds the synthetic-only profile. `DashboardResponseV1` preserves the old non-null commitment contract; `DashboardResponse` v2 explicitly permits an unavailable commitment while retaining three ordered distinct scenarios. Structural schemas do not replace semantic replay, source-hash checks, signature recovery or SQL append-only/transaction checks. `scripts/replay-demo-session.ts` requires the exact archived dependency/source revision and replays the committed semantic objects, not unbound parallel fields.
