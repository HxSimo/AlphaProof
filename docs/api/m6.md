# M6 evaluation, commitment and export API

M6 retains every M3/M4 endpoint and adds canonical read-only resources:

```text
GET /v1/experiments/{experimentId}/eligibility
GET /v1/experiments/{experimentId}/audit-events
GET /v1/experiments/{experimentId}/commitments
GET /v1/commitments/{batchId}/proofs/{leafHash}
GET /v1/exports/{exportId}
GET /v1/experiments/{experimentId}/dashboard
```

Eligibility returns the append-only report history, including superseded receipts. Audit events expose deterministic sequence and predecessor hashes. Commitment and proof reads expose canonical backend objects; the API never infers finality from elapsed time. Exports are validated against the supported schema and engine versions before persistence and again by independent replay.

The dashboard response contains exactly three ordered capital scenarios, their latest common-format checkpoint and descriptive evaluation, both fixed references, latest eligibility report, selected commitment/proof/registry receipt, incidents, limitations and the fixed correlated-sample label. The web application parses this response and formats integer USDC units; it does not calculate portfolio state or eligibility.

All endpoints inherit the stable M3 error envelope. Missing proofs or exports fail with `EXPORT_INCOMPLETE`; invalid experiment state fails with an experiment error. No M6 route allocates funds or mutates an agent decision.
